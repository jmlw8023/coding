## 阶段定义（全章节通用）

| 阶段 | 标志 | 你的状态 |
|------|------|----------|
| **入门** | 跟着教程能跑通 | 还在抄 demo，能改参数 |
| **进阶** | 能独立完成一个完整模块 | 能选型、能调参、能解释 |
| **高级** | 能在生产/真实数据上跑 | 能评估、能优化、能 debug |
| **专家** | 能读论文/源码并改进 | 能设计、能教别人、能解决新问题 |

## 三种推荐学习路径

### 路径 A：RAG 工程方向（最快出活）
`00 → 01 → 05 → 06 → 07.项目1`
适合：想最快做出一个企业知识库 / 文档问答系统。

### 路径 B：Agent / Skill 自动化方向（最贴合 Claude Code 生态）
`00 → 02 → 03 → 05 → 07.项目2`
适合：想把日常工作流自动化、构建 AI 编程协作系统。

### 路径 C：模型方向（最有壁垒）
`00 → 04 → 01 → 05 → 06 → 07.项目3`
适合：想理解到「能改模型」的程度，长期看最不容易被替代。

> **不要并行三条路径**，会拖到哪条都学不完。建议先 A 出第一个能跑的系统，再回头补 B 或 C。

## 如何使用本路线

1. **每章 README 都是一个 checklist**：从入门到专家逐条打勾，不跳级。
2. **每个 stage 有「配套 notebook」表**：能跑代码就直接打开 notebook，不能跑就读 README 的「动手任务 + 推荐资源」。
3. **每阶段结束都做一次「能力检验」**：能讲清、能 demo、能 debug，才算通过。
4. **遇到不会的随时回到 [00-基础](00-基础-Foundations/) 查漏补缺**。

---

## 反模式 — 别这样学

- ❌ **只看不写**：看完一个教程觉得「懂了」，但从没自己改过一行代码。
- ❌ **追新潮**：每周换框架，从没把一个跑到生产。
- ❌ **跳过评估**：做出来不知道好不好，就开始做下一个。
- ❌ **过早分布式**：单机都没跑过 LoRA，就想搞 8 卡 FSDP。
- ❌ **过度抽象**：第一个 RAG demo 就想做成「通用框架」。
- ❌ **忽略数据**：花 90% 时间调模型，花 10% 时间看数据 —— 应该反过来。
