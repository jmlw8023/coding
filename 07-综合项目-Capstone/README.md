## 项目 1：企业知识库 RAG 系统

> **一句话**：把一份「真实复杂」的中文文档集合（手册 / 合同 / 政策 / 技术文档）做成可问答、可引用、可追溯、可自动评估、可在线监控的服务。
>
> **覆盖章节**：[01-RAG](../01-RAG/)（主）+ [05-评估](../05-评估与可观测性-Evaluation/) + [06-部署](../06-工程化与部署-Deployment/)。可选叠 [02-Agent](../02-Agent/)。

### 目标与验收标准
- ✅ 至少 50 份真实文档（PDF/DOCX/MD 混合），总量 > 200 万字
- ✅ 检索 Hit@5 ≥ 0.75，答案忠实度 ≥ 0.85（RAGAS + 自定义 judge）
- ✅ p95 延迟 ≤ 3s（检索 + 生成）
- ✅ 支持增量入库 / 文档版本 / 删除 / 引用回链
- ✅ 接入 Langfuse，能看 trace、查失败 case
- ✅ 30+ 题 eval set + CI 跑回归
- ✅ Docker 一键部署 + README 含架构图

### 阶段拆分（5 个 sprint，每 sprint ~1 周）
1. **数据闭环**：收集文档（最难一步）+ loader 实现（PDF/DOCX/MD）+ metadata schema
2. **朴素 RAG**：复用 [rag_project/](../../rag_project/) 骨架；30 题 eval baseline
3. **迭代检索质量**：嵌入对比 + chunk 策略 + hybrid + reranker，每轮跑 eval
4. **服务化**：FastAPI + 流式 + Docker compose + Langfuse
5. **上线与评估**：CI 接 eval + 架构图 + demo 视频 + 2-3 用户试用 + 再迭代

### 复用本地仓库
- [rag_project/](../../rag_project/) —— 主骨架
- [rag-in-action/](../../rag-in-action/) —— 各模块参考
- [ragflow/](../../ragflow/) —— 生产级架构灵感
- [RAG-Anything/](../../RAG-Anything/) —— 多模态可选叠加

### 交付物清单
- [ ] `kb-rag/` 仓库（FastAPI + Docker）
- [ ] `eval/eval_v1.jsonl`（≥ 30 题）
- [ ] `eval/baseline.md`（每次改动一列）
- [ ] `docs/architecture.md` + 架构图
- [ ] Langfuse dashboard 截图 / 链接
- [ ] 5 分钟 demo（视频或现场）

### 简历模板
> 设计并实现企业知识库 RAG 系统，索引 50+ 文档（200 万字），上线后 p95 延迟 < 3s，Hit@5 0.78（baseline 0.52，通过 hybrid 检索 + bge-reranker 提升），接入 Langfuse 完成失败 case 自动归档与 CI 回归。技术：FastAPI / ChromaDB / Ollama / bge-m3 / RAGAS / Docker。

## 项目 2：研究 / 信息聚合 Agent

> **一句话**：做一个 Agent，给定研究话题（如「最近 3 个月 RAG 评估方面的进展」），它会自主搜资料、读文章、做笔记、写综述，并把过程沉淀成 Skill 让下次更快。
>
> **覆盖章节**：[02-Agent](../02-Agent/)（主）+ [03-Skills](../03-Claude-Skills/) + [05-评估](../05-评估与可观测性-Evaluation/)。可选 [01-RAG](../01-RAG/)。

### 目标与验收标准
- ✅ Agent 能从「一句话话题」自主完成「搜 → 筛 → 读 → 写」全流程
- ✅ 至少 3 个工具：web 搜索、网页读取、笔记存储；可选 RAG 长期记忆
- ✅ 失败可恢复（步骤记 checkpoint，断点续跑）
- ✅ 输出综述 ≥ 1500 字，含引用、来源链接、关键结论
- ✅ Trajectory eval：10 个不同复杂度话题，成功率 ≥ 70%
- ✅ 核心流程封成 Claude Skill（`/research-topic`）

### 阶段拆分（4 个 sprint）
1. **单 Agent + 单工具**：从 [02 入门最小 Agent](../02-Agent/) 起步，加 1 工具，接 trace
2. **工具集**：web 搜索（[Tavily](https://tavily.com/) / SerpAPI / 自建）+ 网页正文（Readability / trafilatura）+ 输出存储 + token / 步数预算
3. **质量与控制**：Plan-then-execute（先 outline 再分段）+ 失败重试 + HITL 介入点 + trajectory log → 10 题成功率评估
4. **Skill 化 + 长期记忆**：流程封 `~/.claude/skills/research-topic/SKILL.md` + 历史综述向量库记忆 + 端到端 demo

### 复用本地仓库
- [rag_project/](../../rag_project/) —— 长期记忆模块借用
- [ragflow/agent/](../../ragflow/agent) —— 企业 Agent 设计参考

### 交付物清单
- [ ] `research-agent/` 仓库
- [ ] `~/.claude/skills/research-topic/SKILL.md`
- [ ] 10 个测试话题 + 输出样本
- [ ] `eval/trajectory_eval.md` 评估报告
- [ ] demo

### 简历模板

## 项目 3：领域微调 + RAG 混合系统

> **一句话**：选一个具体领域（你熟悉的，如数据库 / 金融报表 / 医学影像报告……），用「连续预训练或 SFT 微调」+「领域 RAG」做出领域专家模型 / 服务，证明这套组合**优于纯 RAG** 与**优于纯微调**。
>
> **覆盖章节**：[04-微调](../04-模型微调-Finetuning/)（主）+ [01-RAG](../01-RAG/) + [05-评估](../05-评估与可观测性-Evaluation/) + [06-部署](../06-工程化与部署-Deployment/)。

### 目标与验收标准
- ✅ 领域：100–500 条高质量 SFT 数据 + 200+ 文档 RAG 库
- ✅ 至少 3 个对照组：
  1. 通用模型 + RAG
  2. 微调模型 + 无 RAG
  3. **微调模型 + RAG**（目标 winner）
- ✅ 领域 eval set（≥ 30 题）上，方案 3 显著优于 1 / 2
- ✅ 输出量化模型（GGUF / AWQ）+ vLLM/Ollama 部署
- ✅ 实验记录完整（wandb / mlflow）

### 阶段拆分（6 个 sprint）
1. **选领域 + 准备数据**：≥ 200 文档；造 100–500 SFT 数据（人 + LLM + 人工抽检）
2. **baseline**：通用模型 + RAG（对照组 1）+ 30 题 eval
3. **微调跑通**：ft env 跑 QLoRA 7B SFT；对照组 2
4. **组合**：微调模型 + RAG（对照组 3）+ 失败 case 分析
5. **优化**：DPO 偏好优化 + embedding / reranker 领域微调
6. **部署**：LoRA merge → 量化（GGUF / AWQ）→ vLLM / Ollama + FastAPI + 监控

### 复用本地仓库
- [rag_project/](../../rag_project/) —— RAG 部分
- 新建 `ft env`（见 [04 章](../04-模型微调-Finetuning/)）

### 交付物清单

- [ ] `models/` 目录（LoRA 权重 + GGUF 导出）
- [ ] `eval/comparison.md`（三组对照表）
- [ ] 部署脚本 + 服务镜像
- [ ] 一篇技术博客或内部分享（**强推**，沉淀最重要）

### 简历模板

## 项目 4：多模态文档助手

> **一句话**：用户上传含图、表、公式的复杂文档（论文 / 年报 / 技术规格书），系统能基于文字 + 图 + 表混合检索做问答，并在答案里指明「这个数字来自第 N 页表 3」。
>
> **覆盖章节**：[01-RAG 高级](../01-RAG/) + [05-评估](../05-评估与可观测性-Evaluation/) + [06-部署](../06-工程化与部署-Deployment/)。

### 目标与验收标准
- ✅ 支持 PDF（含扫描件）、PPT、Word、Markdown 输入
- ✅ 图、表、文本统一索引（[RAG-Anything](../../RAG-Anything/) 或自建）
- ✅ 答案能定位到「第 N 页 / 第 M 个表」
- ✅ 30 题 eval（含 5 题图相关 / 5 题表相关），整体准确率 ≥ 0.7
- ✅ Web 前端展示原文片段 + 图

### 阶段拆分（4 个 sprint）
1. **解析器评估**：pypdfium2 / MinerU / unstructured / PaddleOCR 在中文带图 PDF 上对比；选定一家把 50 份文档解析成结构化中间表示
2. **多模态索引**：文本（bge-m3 / nomic）+ 图（jina-clip / CLIP / bge-vl）+ 表（Markdown 入文本索引或转 SQL）；参考 [RAG-Anything](../../RAG-Anything/)
3. **混合检索 + 生成**：检索同时召文本/图/表；vision LLM 描述图后拼 context；答案末尾附 source
4. **前端 + 评估**：Streamlit / Next.js 简易前端 + 30 题 eval + 部署 + 监控

- [RAG-Anything/](../../RAG-Anything/) —— **主参考**，强烈建议先吃透 examples
- [rag_project/](../../rag_project/) —— 文本 RAG 骨架可移植

- [ ] 解析器评估报告（哪种 PDF 用哪种解析器）
- [ ] 30 题 eval（含图表）
- [ ] 简易前端
- [ ] demo

## 一些过来人提醒

- **不要 4 个项目同时开**：你会一个都做不完
- **做完一个项目之后写一篇博客 / 内部分享**：不写 = 没沉淀
- **每个项目都要走完「数据 → 评估 → 部署」全循环**：哪怕规模小，全链路是关键
- **代码留住**：每个项目独立 git 仓 + README，3 个月后回看不至于陌生
- **碰到瓶颈就回到对应章节**：本章不是孤立的，是 01–06 的试炼场
- **进度记录**：建议每个项目仓维护 `LOG.md`，每天 3 行（做了什么 / 卡在哪 / 明天做什么）

## 反模式

- ❌ **四个项目同时开**：必然一个都做不完
- ❌ **只跑通不上线**：错过「真实用户反馈」这块最贵的训练数据
- ❌ **不写博客 / 不留 README**：3 个月回看面试讲不清自己干了什么
- ❌ **盲追新模型**：项目核心是「端到端流程能跑」，不是「用了最新论文」
- ❌ **代码散在 jupyter**：交付一定要 git 仓 + 模块化 + 可复现脚本
